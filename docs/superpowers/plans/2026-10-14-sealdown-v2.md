# sealdown v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add link previews, file opening, password protection, a CodeMirror editor with Mermaid lint, an insert-diagram menu, presentation mode, QR codes and privacy-safe PostHog metrics to the live sealdown.

**Architecture:** Same SPA and modules as v1. New: `src/analytics.ts` (lazy PostHog with a URL-stripping `before_send`), `src/share/password.ts` (PBKDF2 + AES-GCM), two route kinds, `src/editor/` (CodeMirror chunk, lint, templates), `src/ui/Presentation.tsx`. No database change.

**Tech Stack:** v1 stack + posthog-js, codemirror 6 (`codemirror`, `@codemirror/lang-markdown`, `@codemirror/lint`), qrcode.

**Spec:** `docs/superpowers/specs/2026-10-14-sealdown-v2-design.md`

## Global Constraints

- English code/comments/commits; UI strings only in `src/i18n/locales/{en,pt}.ts`.
- PBKDF2-SHA256 600000 iterations, 16-byte salt, AES-GCM 256, bytes `salt || iv || ct`.
- Routes `#/p/<payload>` (inline protected) and `#/q/<id>` (stored protected); inline when payload ≤ 4096 chars.
- PostHog: `persistence: 'memory'`, `autocapture: false`, `capture_pageview: false`, `capture_pageleave: false`, `disable_session_recording: true`, `disable_compression: true` (tiny traffic; lets the e2e inspect exactly what is sent); every event has `app: 'sealdown'`; no URL property may keep a query or fragment.
- QR only for links ≤ 2000 chars. File open limit 5 MB. Lint debounce 600 ms.
- Merge each batch straight to `main` once green (user preference).

## Review Focus

1. **A PostHog property other than `$current_url` carrying the fragment** (e.g. `$referrer`, `$initial_current_url`, `$pathname` variants) → the sanitizer rewrites every string property that parses as an http(s) URL, not a fixed list. Pinned in Task 1.
2. **Wrong password on a stored protected link** → must not refetch from storage on each retry (no extra `get_doc` calls bumping access); bytes are fetched once. Pinned in Task 8.
3. **Presentation of a document whose `---` is inside a code block** → only real horizontal rules split slides; code stays intact. Pinned in Task 10 (split operates on sanitized HTML `<hr>` at top level).
4. **Dropping a non-text file (image) on the editor** → refused with a message, editor unchanged. Pinned in Task 6.
5. **Editor tests on large documents** → CodeMirror virtualizes lines; tests reading text use the editor state through the visible `.cm-line`s only for small docs. Pinned in Task 4 helper.
