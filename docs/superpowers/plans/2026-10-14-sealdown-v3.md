# sealdown v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Write/Split/Read modes with scroll sync, formatting toolbar, callouts, copy code, diagram expand/copy, line numbers, status bar, document title, front matter, extra syntax, typeset styles, paper preview and a command palette.

**Architecture:** Rendering additions are markdown-it plugins plus hydration steps (`src/render/`). Editor additions are CodeMirror extensions and pure formatting functions (`src/editor/`). UI additions in `src/ui/`. Every step keeps the v1/v2 sanitizer as the trust boundary.

**Tech Stack:** v2 stack + markdown-it-github-alerts, markdown-it-footnote, markdown-it-mark, markdown-it-emoji, markdown-it-front-matter.

**Spec:** `docs/superpowers/specs/2026-10-14-sealdown-v3-design.md`

## Global Constraints

- English code; UI strings only in locales (en + pt). Every new control has an accessible name.
- New prefs: `sealdown.mode`, `sealdown.syncScroll`, `sealdown.typeset` — through `readPref`/`writePref`.
- Split needs viewport ≥ 900 px. Reading speed 200 wpm, minimum 1 min.
- No new event may carry document text, titles or URLs.
- Batches A, B, C each: full suites (unit, db, e2e, stored, visual) green → merge to `main` → watch deploy.

## Review Focus

1. **Plugin HTML vs sanitizer** — callout icons (SVG), footnote back-references and front-matter tables must survive DOMPurify while the XSS battery still passes. Pinned in Tasks 3, 9, 10 by adding plugin output to sanitize tests.
2. **Formatting with multi-line or empty selections and at document edges** → no lost text, toggling restores the original. Pinned in Task 2 unit tests.
3. **Scroll sync on documents with front matter or long code blocks** → target lookup uses the nearest preceding source line. Pinned in Task 1 unit tests.
4. **Command palette shortcut inside CodeMirror** → Ctrl/Cmd+K opens the palette instead of a CodeMirror binding, and doesn't fire in the reader's password field. Pinned in Task 13.
5. **Typeset and paper styles in presentation and print** → slides use the typeset but not the card; print has no card or status lines. Pinned in Tasks 11–12.
