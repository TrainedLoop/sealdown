# sealdown Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static site on GitHub Pages where you paste or type Markdown (with Mermaid, KaTeX and code), preview it, and share a link that opens a clean rendered page; small documents live in the URL, large ones are encrypted in the browser and stored in Supabase.

**Architecture:** React SPA with hash routing. Four modules with small interfaces: `share` (codec, crypto, link decisions), `storage` (the only code that talks to Supabase, via plain `fetch` to RPC endpoints), `render` (markdown-it → DOMPurify → placeholders, then lazy hydration of Mermaid/KaTeX/highlight.js), and `ui`. Supabase exposes only three `security definer` RPCs; the table itself has RLS with no policies.

**Tech Stack:** React 19, Vite, TypeScript, pnpm, i18next/react-i18next, oxlint, markdown-it (+ markdown-it-anchor, markdown-it-task-lists, @mdit/plugin-tex), DOMPurify, mermaid (+ @mermaid-js/mermaid-zenuml), KaTeX, highlight.js, Vitest + jsdom, Playwright, Supabase CLI (npm package `supabase`) with pgTAP, GitHub Actions, Renovate.

**Spec:** `docs/superpowers/specs/2026-10-14-sealdown-design.md`

## Global Constraints

- Code, comments, commits, PRs and docs in English; every UI string lives only in `src/i18n/locales/{pt,en}.json`.
- Mirror `../danielporto-site` conventions: `tsconfig.json`/`tsconfig.app.json`/`tsconfig.node.json` layout, `.oxlintrc.json`, `base: process.env.BASE_PATH ?? '/'` in `vite.config.ts`, pnpm.
- Dependencies installed at their latest release; `mermaid` must always be the latest release.
- All route state after `#`; formats exactly `#/`, `#/v/<payload>`, `#/s/<id>.<key>`.
- Inline threshold: encoded payload length **≤ 4096** characters → `v`; otherwise `s`.
- Stored content cap: **1048576** bytes (encrypted bytes, client check + DB constraint).
- Compression: `deflate-raw` via `CompressionStream`/`DecompressionStream`. Encoding: base64url without padding.
- Encryption: AES-GCM, 256-bit key, 12-byte random IV per document, stored bytes = `iv || ciphertext`.
- Supabase id: 10 random base62 characters.
- Prune cap: **419430400** bytes (400 MB), hourly via `pg_cron`, least recently accessed deleted first.
- Mermaid always initialized with `securityLevel: 'strict'`, `startOnLoad: false`.
- Supabase config from `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`; when either is missing, storage behaves as unavailable.
- `localStorage` keys: `sealdown.draft`, `sealdown.theme`, `sealdown.lang`; every access wrapped in `try/catch`.
- TOC shown only when the document has **3 or more** headings (h1–h3).
- Keepalive cron every 3 days.

## Review Focus

1. **Link pasted with trailing junk from chat apps** (a trailing `.`, `)`, `,`, whitespace, or percent-encoding) → the document still opens; neither base64url nor the base62 id use those characters, so the router strips them. Pinned in Task 1.
2. **PNG export of a flowchart with HTML labels** → Mermaid's `foreignObject` labels taint the canvas and `toBlob` throws; expected: PNG downloads. Fix: re-render the source offscreen with `htmlLabels: false` before rasterizing. Pinned in Task 11.
3. **Export PDF while in dark theme** → user expects a printable light document, not white text on a white page. Export switches to light, awaits diagram re-render, prints, restores. Pinned in Task 11.
4. **One broken diagram among valid ones** → the valid ones render, the broken one shows the error box, and Mermaid's error leftovers (`#d<id>` nodes it appends to `<body>`) are removed. Pinned in Task 9.
5. **In-document anchor link `[x](#intro)` clicked on the reader page** → scrolls to the heading, URL hash unchanged, document stays open. Pinned in Task 11.
