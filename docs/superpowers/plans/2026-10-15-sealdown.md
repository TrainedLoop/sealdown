# Sealdown Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename rendermd to Sealdown everywhere, encrypt every link, and rebuild the UI in the "Vault" identity with a seal modal, an unseal screen, typeset styles, a command palette and Mermaid hints.

**Architecture:** Same modules. `share/link.ts` gains the `#/e/` format; `ui/` gets a top bar, seal modal and unseal card; a storage-key migration runs before anything reads prefs; the database schema is renamed by a one-off SQL plus a rewritten base migration.

**Tech Stack:** unchanged (React 19, Vite, CodeMirror 6, markdown-it, Mermaid, Supabase + dbmate, Playwright).

**Spec:** `docs/superpowers/specs/2026-10-15-sealdown-design.md`

## Global Constraints

- No `rendermd` anywhere except the redirect repository and the storage-key migration's list of old keys.
- English UI by default, Portuguese via toggle; every string in both locales.
- Every generated link is encrypted (`#/e/`, `#/s/`, `#/p/`, `#/q/`); `#/v/` is read-only legacy.
- Production order: one-off SQL → exposed schemas (owner) → deploy.
- Batches are merged to `main` when every suite is green.

## Review Focus

1. **Old `#/v/`, `#/s/`, `#/p/`, `#/q/` links** keep opening after every batch (fixtures pinned in Task 1 and re-run after the rename).
2. **Storage-key migration** never overwrites a newer value and runs before i18n/theme read their prefs.
3. **Schema rename** keeps stored documents readable and dbmate's history consistent (`status` shows the base migration applied).
4. **Seal modal focus and clipboard**: the link is copied on success, focus moves into the modal and back on close, Esc closes.
5. **Contrast** in both themes for the new palette (text and accent on surfaces ≥ WCAG AA).
